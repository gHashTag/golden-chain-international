# Literature search — W-INTL-266

The literature search was run in parallel with the implementation of
`research/framed_helper_contract.py`, not after it. The candidate contribution is
narrow: a finite, versioned, length-delimited parser control for the packed helper
candidate. It is not a cryptographic construction.

## Directly checked sources

1. **Robust and Reusable Fuzzy Extractors for Low-entropy Rate Randomness Sources**
   — Somnath Panja, Shaoquan Jiang, Reihaneh Safavi-Naini, 7 May 2024.
   [arXiv:2405.04021](https://arxiv.org/abs/2405.04021) defines robustness so that
   tampering with helper data is detectable, and describes strongly robust and
   reusable fuzzy extractors using an information-theoretic MAC. This is direct
   prior art for the security property. The present control does not reproduce
   their construction and does not claim robustness or security; it only makes
   canonical parsing and a software integrity witness executable.

2. **Information Theoretic Analysis of PUF-Based Tamper Protection**
   — Georg Maringer, Matthias Hiller, 5 February 2025.
   [arXiv:2502.03221](https://arxiv.org/abs/2502.03221) studies helper-data
   algorithms, finite-blocklength limits, attacker models, and converse bounds
   for PUF-based tamper protection. It supplies boundary conditions for reading
   the finite control: frame rejection is not a finite-blocklength security
   guarantee, and the control does not instantiate the paper's threat model.

3. **Machine Learning of Physical Unclonable Functions using Helper Data -
   Revealing a Pitfall in the Fuzzy Commitment Scheme** — Emanuele Strieder,
   Christoph Frisch, Michael Pehl, 16 December 2020.
   [IACR ePrint 2020/888](https://eprint.iacr.org/2020/888) shows that public
   helper data and the redundancy of linear codes, including BCH, can expose
   learnable structure. This is a warning against turning a parser or digest
   count into a leakage claim. It is prior art and a threat boundary, not a
   numerical input to the new model.

4. **Lightweight (Reverse) Fuzzy Extractor with Multiple Referenced PUF
   Responses** — Yansong Gao, Yang Su, Lei Xu, Damith C. Ranasinghe, 19 November
   2018.
   [arXiv:1805.07487](https://arxiv.org/abs/1805.07487) is an adjacent
   implementation line on reducing error-correction overhead in fuzzy extractors.
   It does not provide the versioned framing control measured here.

## Position after the search

The direct checks found prior art for robust helper-data tamper detection and for
public-helper-data leakage. Therefore W-INTL-266 is not a claim of a new robust
fuzzy extractor, MAC, or security theorem. Its bounded result is an engineering
interface control: 64/64 canonical frames parse, while 64/64 truncations,
extensions, wrong-version frames, wrong-format frames, and payload mutations are
rejected by the finite software parser and digest witness. The digest is not a
keyed authenticator. Deployment, leakage, active-attacker analysis, area, timing,
FPGA behavior, and the G16 three-node shared-uplink demonstration remain open.
