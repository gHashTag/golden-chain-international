# Literature note — rollback anchor and persistent recovery — 2026-09-06

The search was run in parallel with the implementation of `research/rollback_anchor_control.py`, not after it. Search terms covered crash-consistent dual-slot journals, monotone counters, rollback-resistant storage, torn writes, and recovery ordering.

## Sources checked

- [TEE Is Not a Healer: Rollback-Resistant Reliable Storage](https://arxiv.org/html/2505.18648v3) — the search result describes TEE-Rex and explicitly separates recovery from durable storage and specialised monotone hardware. This is a direct boundary for the present control: a software anchor is not evidence that ordinary storage supplies an irreversible counter. [prior art]
- [Anchor: A Library for Building Secure Persistent Memory Systems](https://dse.in.tum.de/wp-content/uploads/2024/01/Anchor-SIGMOD.pdf) — the result reports a trusted monotonic-counter cost and a crash-consistency mechanism for persistent-memory operations. It is a systems design with storage assumptions, not a reproduction of this finite journal model. [prior art]
- [Torn write prevention on Amazon EC2 Linux instances](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/storage-twp.html) — AWS documents torn-write prevention as a block-storage feature for incomplete writes. This supports treating the two-slot fallback and the independent anchor as separate questions. [prior art]
- [Machine-Checked Dual-Write Recovery from a Committed ...](https://arxiv.org/html/2608.00501v4) — the result frames recovery around a durable accepted record and separately recorded progress. That is adjacent to the distinction between the journal record and the anti-rollback witness; it does not evaluate this repository's byte layout. [adjacent]
- [PostgreSQL full-page writes](https://wiki.postgresql.org/wiki/Full_page_writes) — the documented old-page/new-page invariant is a deployed database recovery pattern, not evidence of power-loss ordering for this project. [prior art]
- [TEE Is Not a Healer: Dagstuhl version](https://drops.dagstuhl.de/storage/00lipics/lipics-vol356-disc2025/html/LIPIcs.DISC.2025.39/LIPIcs.DISC.2025.39.html), [Rebound](https://arxiv.org/abs/2511.13641), [CRISP](https://arxiv.org/abs/2408.06822), and [Chimera](https://arxiv.org/abs/2606.09101) were already recorded in the preceding journal loop and were retained as rollback/recovery boundaries rather than counted as new results.

## Positioning decision

No source above makes the finite software result a new journal or security protocol. The non-duplicate contribution selected for W-INTL-273 is narrower: measure the missing state boundary when both journal slots are valid but have been restored to an older generation, using a separate monotone anchor in the model. The result is labelled `[measured]` software and `[proved]` finite parser/state properties. Device power-loss ordering, filesystem durability, write barriers, hardware monotonic counters, trusted execution, distributed recovery, leakage, active attacks, area, timing, FPGA integration, and the G16 three-node shared-uplink demonstration remain `[open conjecture]`.

The finite-blocklength PUF bounds in [arXiv:2502.03221](https://arxiv.org/abs/2502.03221) remain prior art for the surrounding PUF construction; they are not used to claim a rollback result here.
