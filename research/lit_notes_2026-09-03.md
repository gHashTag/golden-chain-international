# Literature note - 2026-09-03 - W-INTL-270

The literature search ran in parallel with the implementation of `research/sequence_boundary_control.py`. The question was whether explicitly exercising an unsigned sequence field's endpoints and an apparent rollover adds a protocol contribution or only makes a selected boundary auditable.

## Directly checked sources

- [Serial Number Arithmetic](https://www.rfc-editor.org/rfc/rfc1982), RFC 1982, March 1996. Sections 2–3 define a finite serial-number space whose maximum is one less than a power of two, define bounded modular addition, and give half-range comparison rules with pairs whose ordering is undefined. This is direct prior art for the rollover boundary.
- [IPsec Anti-Replay Algorithm without Bit Shifting](https://www.rfc-editor.org/rfc/rfc6479), RFC 6479, January 2012. Sections 1–3 describe a bitmap anti-replay window and document a sequence-zero condition labelled initial-or-wrapped in the implementation. This is direct prior art for the adjacent freshness state, not a security result for this repository.
- [A lightweight PUF-based authentication protocol](https://arxiv.org/abs/2405.13146), arXiv:2405.13146. The checked metadata places sequence/freshness decisions in the surrounding PUF-authentication protocol setting. It does not establish a result for this finite boundary control.
- [Secure PUF-Based Authentication Systems](https://pmc.ncbi.nlm.nih.gov/articles/PMC11487452/). The checked review treats replay and freshness as protocol threat boundaries. It is context, not evidence that the present implementation is deployed or secure.

The first two RFCs are the important prior art. The control intentionally selects a strict non-wrapping state policy at the verifier boundary, while RFC 1982 demonstrates that a protocol may instead define bounded modular addition and half-range comparisons. No new arithmetic rule, anti-replay mechanism, or security theorem is claimed.

## What is measured

[measured] With seed 20260903 and 64 trials, the endpoint control accepts 64/64 sequence-zero frames and 64/64 maximum-value frames. It rejects 64/64 values above the unsigned 64-bit maximum, 64/64 negative values, and 128/128 non-integer representations. A maximum-to-zero apparent rollover is rejected 64/64, and the failed transition leaves the verifier's high-water mark and bitmap unchanged in every trial.
