# Literature note — 2026-08-20

## Search run in parallel with W-INTL-263

The search target was the open helper-data encoding and leakage boundary left by W-INTL-262. The implementation was run in parallel with this search; no literature number was copied into the model.

### Directly checked prior art

- **Hiller, Pehl, Kramer and Sigl, “Algebraic Security Analysis of Key Generation with Physical Unclonable Functions.”** The direct IACR record is https://eprint.iacr.org/2016/854. It gives a rank criterion for zero leakage in an algebraic PUF key-generation core under nearly uniform responses. Tag: [prior art]. The present module uses rank only to derive a lossless finite coordinate encoding; it does not apply that criterion as a security proof.
- **Strieder, Frisch and Pehl, “Machine Learning of Physical Unclonable Functions using Helper Data — Revealing a Pitfall in the Fuzzy Commitment Scheme.”** The direct IACR record is https://eprint.iacr.org/2020/888. It reports that public helper data and code redundancy can expose learnable information and that BCH constructions are affected in its attack setting. Tag: [threat]. The present module therefore does not interpret fewer stored bits as lower leakage.
- **Maringer and Hiller, “Information Theoretic Analysis of PUF-Based Tamper Protection.”** The direct arXiv record is https://arxiv.org/abs/2502.03221. It gives finite-blocklength lower bounds, converse bounds, and zero-leakage helper-data constructions under stated attacker models. Tag: [prior art]. It is not a numerical source for the finite coordinate counts below.
- **Ruchti, Gruber and Pehl, “When the Decoder Has to Look Twice: Glitching a PUF Error Correction.”** The direct IACR record is https://eprint.iacr.org/2021/958. It reports a hardware fault attack and discusses limits of helper-data hashing countermeasures. Tag: [threat]. The new module has no hardware or side-channel claim.

## Consequence for this loop

The non-duplicating contribution is a finite representation control: derive the binary rank of the repository's BCH(127,57,11) parity-check map and encode the six syndrome helpers in basis coordinates. It is an engineering reproduction of the syndrome-space dimension, not a new leakage result. The prior art makes the boundary explicit: `924` emitted syndrome bits can be reduced to `420` semantic coordinate bits without implying `504` bits of security gain or a deployed helper-data format.
