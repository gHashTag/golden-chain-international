# Literature note - 2026-09-04 - W-INTL-271

The literature search ran in parallel with the implementation of `research/freshness_checkpoint_control.py`. The question was whether a persistent checkpoint boundary around the finite sliding-window state is a new protocol result or a bounded reproduction of rollback-resistant storage practice.

## Directly checked sources

- [TEE Is Not a Healer: Rollback-Resistant Reliable Storage](https://drops.dagstuhl.de/storage/00lipics/lipics-vol356-disc2025/html/LIPIcs.DISC.2025.39/LIPIcs.DISC.2025.39.html), Sadegh Keshavarzi, Gregory Chockler, and Alexey Gotsman, DISC 2025. The paper states that sealing can show that a stored state was written by the TEE but cannot show that it is the most recent version. It distinguishes crash-consistent writes from rollback and discusses monotonic counters and distributed incarnation numbers. This is direct prior art for the open persistent-state boundary.
- [Chimera: Protocol-Aware Recovery for Confidential BFT Consensus](https://arxiv.org/abs/2606.09101), Tong Liu et al., 2026. The abstract describes recovery from stale persistent state after a crash, separates metadata and logs, and formalises safety and liveness. This is a current protocol-level threat and a reminder that a single local checkpoint does not establish distributed recovery.
- [It's a Feature, Not a Bug: Secure and Auditable State Rollback for Confidential Cloud Applications](https://arxiv.org/abs/2511.13641), Quinn Burke, Anjo Vahldiek-Oberwagner, Michael Swift, and Patrick McDaniel, 2025. The abstract distinguishes authorised rollback from malicious replay and treats atomic state updates and auditable versioning as separate mechanisms. It prevents the finite checkpoint control from being described as a complete rollback policy.
- [CRISP: Confidentiality, Rollback, and Integrity Storage Protection for Confidential Cloud-Native Computing](https://arxiv.org/abs/2408.06822), Ardhi Putra Pratama Hartono, Andrey Brito, and Christof Fetzer. The checked abstract states that TEE integrity does not extend to state saved on disk and that restart-time rollback is a distinct threat. This is context for the boundary, not an implementation claim here.
- [Analysis of PUF-Based Mutual Information and Finite Blocklength Bounds](https://arxiv.org/abs/2502.03221), Maringer and Hiller, 2025. This is the already checked prior art for the project's finite-blocklength PUF bounds. It is not a source for the checkpoint encoding; the relevant lesson is the same: any result that overlaps a cited finite model must be labelled as a reproduction/control rather than a new theorem.

The result is therefore deliberately narrow. The repository adds a canonical 48-byte checkpoint encoding, a digest witness, an explicit eight-bit bitmap-domain check, and a forward-generation application rule. It does not reproduce a trusted monotonic counter, crash-consistent storage, a distributed quorum, or rollback-resistant deployment.

## What is measured

[measured] With seed 20260904 and 64 deterministic trials, canonical checkpoints round-trip 64/64; checksum mutations are rejected 64/64; truncated and extended encodings are rejected 128/128; out-of-window bitmap values are rejected 64/64; stale generations are rejected 64/64 without changing the active state; and strictly newer generations are accepted 64/64. The wire size is 48 bytes for the fixed layout.

[proved] For the fixed parser and state machine, malformed and stale checkpoints cannot update the active in-memory state, while a canonical checkpoint round-trips. [open conjecture] Ordinary-storage rollback resistance, crash atomicity, distributed ordering, recovery after partial writes, key management, leakage, active attacks, side channels, area, timing, FPGA integration, and G16 remain unmeasured.
